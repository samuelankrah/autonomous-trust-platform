# Workshop tests

## AT-05 parity harness

`parity.js` is the AT-05 machinery: the durable check that the
JavaScript workshop engine matches the Python reference engine under
`scenario-contract-v1`, as defined in the Parity definition section of
`docs/workshop/scenario-contract-v1.md`.

### How to run

From the repository root:

```sh
node workshop/tests/parity.js
```

It prints a per scenario, per seed report and a summary line such as
`Parity: 14/14 against scenario-contract-v1`, writes the same report to
`parity-report.txt` in this directory (regenerated on every run), and
exits 0 only when every comparison passes. No dependencies beyond
Node itself.

### What it checks

- The scenario list, seed list, and contract version come from
  `docs/workshop/fixtures/index.json`. Fixtures are enumerated from
  the index entries, never hardcoded.
- For each entry, the engine's fixture shaped output from
  `runScenario(scenario, seed)` in `workshop/js/fixture.js` is deep
  compared against the fixture file using exactly the contract
  projection: strings byte for byte, numbers and booleans exact, null
  equal only to null, arrays in the same order, objects structurally
  equal with key order ignored. Extra fields on either side are
  failures.
- The contract's seq rule, checked on the engine's full ledger
  records: seq values are integers forming a contiguous sequence,
  each exactly one more than the previous.
- Every fixture verdict is `PASS`, and every engine run verdict is
  `PASS`.

### What a failure means

A failure means the JavaScript engine has drifted from the reference
behavior recorded in the fixtures. Fix the engine, never the fixture.
Fixtures are generated by the reference exporter, never hand-edited;
if reference behavior legitimately changes, fixtures are regenerated
and the contract version is bumped by that process, as the contract's
versioning rule describes.
